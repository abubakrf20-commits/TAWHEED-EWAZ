# فعال‌سازی گزارش خطا (Sentry) در نسخهٔ منتشرشده

## چرا لازم است؟

`lib/main.dart` مقدار DSN را از `--dart-define=SENTRY_DSN=...` می‌خواند و **اگر
خالی باشد، Sentry کاملاً خاموش است**. دستور سادهٔ `flutter build apk --release`
هیچ dart-define ای پاس نمی‌دهد؛ یعنی APK منتشرشده خطاها را گزارش نمی‌کند.

## ۱) ساخت پروژهٔ Sentry

1. در <https://sentry.io> وارد شوید (پلن رایگان کافی است).
2. یک پروژهٔ **Flutter** بسازید و **DSN** را کپی کنید (شکل:
   `https://<key>@o<org>.ingest.sentry.io/<project>`).

> DSN مثل کلید Firebase یک شناسهٔ سمت‌کلاینت است؛ ماهیتاً عمومی است و اجازهٔ
> *نوشتن* رویداد می‌دهد، نه خواندن. به همین دلیل در git ذخیره نمی‌شود ولی
> داخل APK قرار می‌گیرد — این طبیعی است.

## ۲) بیلد با فعال‌سازی گزارش

در PowerShell (ویندوز):

```powershell
$env:SENTRY_DSN = 'https://<key>@o0.ingest.sentry.io/<project>'
pwsh -File tool/build_release.ps1
```

اسکریپت علاوه بر تزریق DSN، در صورت تنظیم‌بودن `$env:APP_REVISION` آن را هم
پاس می‌دهد و با `-SplitPerAbi` بیلد تفکیک‌شدهٔ معماری (arm64-v8a + armeabi-v7a)
می‌سازد:

```powershell
pwsh -File tool/build_release.ps1 -SplitPerAbi
```

اگر DSN تنظیم نشده باشد و `-NoSentry` هم نداده باشید، اسکریپت **عمداً خطا
می‌دهد** تا هیچ‌وقت تصادفی بیلدی بدون گزارش منتشر نشود. برای بیلد آزمایشی محلی:

```powershell
pwsh -File tool/build_release.ps1 -NoSentry
```

## ۳) بررسی درست‌بودن

پس از نصب APK، در Sentry → Issues باید رویدادها دیده شوند. برای تست، می‌توانید
موقتاً یک خطای آزمایشی بیندازید (نباید در نسخهٔ نهایی بماند).

## نکتهٔ حریم خصوصی

گزارش‌ها **فقط اطلاعات فنی** (نوع خطا، نسخهٔ برنامه، مدل دستگاه) هستند و شامل
محتوای شخصی کاربر (متن‌ها، آمار عبادت، موقعیت) نمی‌شوند. این مورد در
`privacy_policy.md` توضیح داده شده است.
