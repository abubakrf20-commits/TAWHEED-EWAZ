## ۰. یافتهٔ کلیدی دربارهٔ quran.ws

**quran.ws سایت قرآن‌خوانی نیست — پلتفرم دادهٔ متن‌باز برای سازندگان اپ‌های قرآنی است**
(«بلوک‌های سازنده»). ترجمه، تفسیر، صوت، محتوای فارسی و ریدرِ کاربر‌نهایی **ندارد**.
پس «کپی کردن» از آن موضوعیت ندارد؛ ارزش آن در **داده‌های آمادهٔ تأییدشده + الگوهای مهندسی** است:

| بلوک | چیست | وضعیت |
| --- | --- | --- |
| Quran Text | متن قرآن در **۷ روایت** (حفص، شعبه، ورش، قلون، دوری، سوسی، بزی) با آدرس‌دهی سوره/آیه/صفحه/جزء/**کلمه** + **هویت مشترک کلمه‌ها** (یک عدد متراکم 1–77,434 یکسان بین هر ۷ روایت) | Beta |
| Qiraat Ayah Map | نگاشت بین ۶ سامانهٔ شمارش آیه (مثلاً حفص 2:255 → ورش 2:253–254) | Stable |
| Quran SVG | ۶۰۴ صفحهٔ وکتوری برای ۵ مصحف + **چندضلعی قابل‌کلیک برای هر آیه** (بدون OCR) | Stable |
| Quran SVG Elements | صفحات شکسته‌شده با **کلمات آدرس‌پذیر** (hit-test کلمه‌ای) | Beta |
| Quran Tajweed | **۱۴۷,۲۵۵ بازهٔ قاعده، ۱۲۷ قاعده، پوشش هر ۶,۲۳۶ آیه** (حفص) به شکل `[start, end, ruleIndex]` | Stable |
| Quran Engine | موتور رندر Rust با پوشش Flutter (dart:ffi + CustomPainter — فقط اندروید، منتشرنشده) | Beta |
| ابزارهای زنده | `text.quran.ws` (فایل‌ساز متن با فرمت txt/json/csv/sql، علامت‌گذاری وقف/سجده، دو املای رسم‌الخط) · `png.quran.ws` (PNG/SVG/PDF شفاف هر بازهٔ آیه با API مستند) · `pdf.quran.ws` (PDF وکتوری مصحف در ۵ قرائت) | بدون کلید/ثبت‌نام |
| اصول | Provenance برای هر داده (منبع، نسخه، **SHA-256**)، لایسنس MIT/CC-BY، راهنماهای ساخت (آفلاین، جستجو، چند روایت، برش تصویر آیه) | — |

نکتهٔ فنی مهم برای ما: دادهٔ متن و کلمات آن با **URL ثابت و بدون کلید** قابل دریافت است؛
درحالی‌که برنامهٔ ما الان برای کلمات/تایم‌استمپ به `apis.quran.foundation` (OAuth + کلید env)
وابسته است. `text.quran.ws` می‌تواند **جایگزین رایگان و بدون کلید** برای لایهٔ متن/کلمه باشد.

## ۱. وضعیت امروز بخش قرآن برنامه (بررسی کامل)

### ۱-۱. فهرست امکانات موجود (هر آنچه کاربر می‌تواند بکند)

**مصحف و خواندن**
- مصحف صفحات QCF4 (چاپ مدینه، نسخهٔ ۴) از سرور خودِ مخزن کاربر (TAWHEED-EWAZ) با دانلود صفحات + فونت + از پیش‌دانلود گروهی (`quran_mushaf_pre_download_sheet.dart`، 1269 خط) و مدیریت حافظهٔ دانلود (`qcf4_download_manager.dart`, `qcf4_data_store.dart`, `qcf4_font_loader.dart`).
- رندر سفارشی صفحه: سرصفحهٔ سورهٔ CustomPaint سلطنتی (`qcf4_surah_header.dart` — جای PNG تثبیت‌شده، نباید برگردد)، نام سوره/جزء روی کاغذ در هر دو حالت، شمارهٔ صفحه موازی آیات، حالت تمام‌صفحه با چیپ خروج (`quran_mushaf_overlays.dart`).
- ۲۲ کاغذ/پالت رنگی با سقف کنتراستِ تضمین‌شده (`mushaf_palette.dart` + تست ۵۰۰ جفت)، هایلایت آیه با ترکیب pre-composited (`mushafLiveAyahWashOn`).
- صفحه‌گردان با چند انیمیشن (`mushaf_page_turn.dart` 741 خط — ورق‌خوردن واقعی با سایهٔ عطف)، تنظیمات صفحه‌گردان (`mushaf_page_turn_settings.dart`).
- قفل افقی/عمودی (دکمهٔ چرخش در هدر + pref مشترک)، پرش به صفحه/سوره/جزء، فهرست سوره/جزء (`quran_surah_list_screen.dart`).
- حاشیه‌نویسی خواندن: نشان‌گذاری (بوکمارک، جدول Drift)، ۶+۲ رنگ هایلایت، یادداشت آیه (دیالوگ از پیش‌پرشده)، اشتراک آیه (متن/تصویر) و بازهٔ آیات و تفسیر (`quran_ayah_share_screen.dart` 488 خط، `quran_tafsir_share_screen.dart` 515 خط).
- شیت اکشن آیه: یک ردیف ۶ تایی + ردیف دوم ۲ تایی (تلاوت/تفسیر/ترجمه/صوتی/هایلایت/نشان + اشتراک/یادداشت) — اخیراً بازطراحی شده.

**صوت**
- تلاوت: `mp3quran_service.dart` (کش محلی، fallback URL، دانلود سوره، watchdog گیرکردن، audio focus، media session)، شیت قاری + دانلود قاری، سرعت/تکرار (شیت گسترده + دیالوگ بازهٔ تکرار)، «ادامه» و حالت پیوسته/غیرپیوسته.
- ترجمهٔ صوتی QuranEnc + حالت «تلاوت سپس ترجمه» (پیش‌فرض روشن) با دیگری‌افت safe به فقط-ترجمه (`quran_translation_audio_controller.dart` 448 خط).
- دنبال‌کردن آیه حین پخش (sheet تنظیم دنبال‌کردن) + پرش صفحهٔ خودکار.

**ترجمه و تفسیر**
- ترجمهٔ فارسی **bundled** (آفلاین از لحظهٔ نصب) + کردی سورانی دانلودی؛ قرارداد واحد JSON 6236 آیه‌ای با index در حافظه (`quran_translation_reader.dart`).
- تفسیر: المختصر bundled (SQLite) + کاتالوگ دانلودی (`tafsir_service.dart`)، نمایش per-ayah با مارک‌آپ (`tafsir_markup.dart`).

**جستجو**
- جستجوی آفلاین عربی سه‌لایه: FTS5 → LIKE → اسکن حافظه (`quran_search_service.dart` 451 خط) — شکست ایندکس یعنی «کند ولی کارکنان»، نه «بی‌نتیجه».
- جستجوی سراسری برنامه (هر تب → پرش به آیه از طریق `quranNavRequestProvider`).
- جستجوی محتوای بخش‌ها در More (`more_content_search.dart` — خارج از این بخش ولی هم‌خانواده).

**هم‌خانواده‌ها (تب قرآن نیستند ولی به آن می‌رسند)**
- مصحف حافظ (`lib/features/hifz`): درس/مرور/گزارش حفظ.
- ختم قرآن (`lib/features/khatm`، ۲۱ فایل): برنامهٔ ختم.
- اذکار/دعا از قرآن و ... جداست.

### ۱-۲. دیزاین
- زبان بصری جدید (کیت duotone، RingView، SectionHeader) به تازگی به ریدر منتقل شده (`quran_kit_row.dart`).
- گزارش بازطراحی `docs/QURAN_REDESIGN_REPORT.md` خودش ۶ یافتهٔ صیقل‌کاری + ۸ پیشنهادِ شماره‌گذاری‌شدهٔ در انتظار تأیید دارد.
- نقاط ضعف دیزاین شناخته‌شده: صفحهٔ بوکمارک‌ها پالت ریدر را نمی‌گیرد (پرش تم شب/روز)، `MushafSettingRow` آخرین ListTile غیر-duotone، دو شیت قاری با chrome تکراری، نتیجهٔ جستجو کلمهٔ جستجو را هایلایت نمی‌کند.

### ۱-۳. معماری و عملکرد
- قوت‌ها: آفلاین‌اول (متن ترجمه bundled، جستجو بدون اینترنت، کش صوت)، تست‌ها ۵۱ فایل، گاردهای صحت مصحف (integrity، encoding)، پالت‌های تست‌شدهٔ کنتراست.
- ضعف‌ها:
  1. **مونولیت ۳,۲۹۳ خطی** `quran_mushaf_view.dart` با فایل‌های part — نقطهٔ اتصال همه‌چیز.
  2. **لایهٔ کلمه نصفه‌کاره**: API کلمات + تایم‌استمپ را می‌گیرد (`quran_api_service.dart` — حتی workaround باگ `by_page`) ولی هیچ UI کلمه‌محوری (هایلایت حین پخش، معنی کلمه، ضربه روی کلمه) روی آن سوار نیست.
  3. **فقط حالت صفحه‌ای**: حالت متنی/اسکرولی (آیه‌به‌آیه) وجود ندارد — برای خواندن ترجمه‌محور ضعف است.
  4. وابستگی به API پولی/کلیددار quran.foundation برای لایهٔ کلمه.
  5. تاجوید رنگی ندارد؛ چند روایت ندارد؛ مقایسهٔ ترجمه ندارد؛ سینک بین دستگاه‌ها ندارد.
  6. کتاب‌شناسی: بوکمارک/هایلایت محلی — بدون riwayah-key (نکتهٔ quran.ws برای آینده).

## ۳. برنامهٔ پیشنهادی ارتقا (اولویت‌بندی‌شده)

### موج ۱ — صیقل و برد سریع (هفته‌ای، بدون تغییر اساسی)
1. هایلایت تطابق در نتایج جستجو (+ گزارش §6.5).
2. رفع پالت بوکمارک‌ها + تبدیل `MushafSettingRow` به duotone + ادغام دو شیت قاری.
3. «ادامهٔ مطالعه» روی خانه (صفحهٔ آخر ذخیره شده؛ کارت resume).
4. یادداشت‌نویسی بوکمارک (ستون note هست، UI نوشتن نیست) + فیلتر/مرتب‌سازی لیست.
5. شمارش نتایج جستجو + جستجوی عبارت.

### موج ۲ — امکانات بزرگ جدید (هر کدام مستقل)
6. **حالت متنی/اسکرولی** (آیه‌به‌آیه، ترجمه زیر متن، فونت/اندازه قابل تنظیم) — رفع بزرگ‌ترین خلأ خواندنی؛ متن را از text.quran.ws یا باندل بگیرید.
7. **کلمه‌به‌کلمه**: الف) هایلایت حین تلاوت با تایم‌استمپ‌های موجود در API layer؛ ب) ضربه روی کلمه → ترجمهٔ آن کلمه (نیازمند گلاسری word — منبع رایگان: هر یک از کاتالوگ‌های متنی).
8. **تاجوید رنگی** (کلید روشن/خاموش) روی حالت متنی با دیتاست quran.ws؛ روی مصحف تصویری ممکن نیست.
9. **مقایسهٔ ترجمه‌ها** (دو ستون در شیت آیه وقتی ≥۲ ترجمه دانلود است — پیشنهاد §7.7 گزارش قبلی).
10. **بازطراحی اشتراک آیه**: رندر وکتوری + قالب‌های مربعی/استوری/بنر (الگوی png.quran.ws) با فوتر ShareService.

### موج ۳ — تغییرات اساسی (اگر «بهترین و جدیدترین» هدف است)
11. **معماری دو-لایهٔ مصحف**: تصویر QCF4 فقط پوستر؛ لایهٔ متن نامرئی با مختصات کلمه روی آن — ضربه دقیق کلمه، انتخاب بازهٔ آیه با کشیدن، هایلایت زنده حین پخش، همه از یک source of truth. (مهاجرت تدریجی از مونولیت ۳,۲۹۳ خطی به ماژول‌های reader/page/word/audio.)
12. **چند روایت** (ورش و…) با Qiraat Ayah Map برای سازگاری بوکمارک/هایلایت — برای مخاطب عرب‌زبان در آینده.
13. **قرارداد provenance داخلی**: هر دارایی دانلودی (مصحف/ترجمه/تفسیر/صوت) با منبع+نسخه+SHA-256 ثبت شود؛ دانلود خراب قبل از رندر رد شود.
14. (اختیاری، بلندمدت) ارزیابی موتور Qvp برای رندر وکتوری صفحه — فقط وقتی پکیج Flutter آن منتشر/پایدار شد؛ الان comment-unpublished است، اتکا به آن زودهنگام است.

### آنچه از quran.ws «همین حالا» قابل مصرف است
- دیتاست تاجوید (JSON کوچک، CC-BY) → موج ۲.۸.
- فایل‌های آمادهٔ متن (per-word، با علامت وقف/سجده، دو رسم‌الخط) → موج ۲.۶/۲.۷ بدون کلید API.
- الگوی SHA-256/provenance → موج ۳.۱۳.
- راهنمای folding جستجو → موج ۱.۵.
- word-identity → پایهٔ داده‌ای موج ۳.۱۱.

### آنچه از quran.ws برنمی‌داریم
- موتور Qvp (منتشرنشده، Android-only، ریسک).
- svg کامل صفحات (حجم/Brotli و رندر سنگین در موبایل نسبت به QCF4 بهینه فعلی).
- هیچ «دیزاینی» — سایت ریدر ندارد؛ الگوهای UI باید از ریدرهای برتر (quran.com/ayah و …) جداگانه سنجیده شوند.

## ۵. بازبینی کامل بقیهٔ بخش‌های مصحف + پیشنهادهای ارتقا (2026-11-06)

### ۵-۱. نتیجهٔ بازبینی عملکرد (خواندنی، بدون باگ باز)
مسیرهای داغ بررسی شدند و سالم‌اند — معماری از قبل مهندسی‌شده است:
- decode صفحات در isolate (با مسیر inline برای صفحات کوچک)؛
- حین cold-load، صفحهٔ قبلی با درخت stale دیده می‌شود (پرش تصویری صفر)؛
- کش‌های عرض کلمه و متریک‌ها LRU-محدود؛ هر پنج تایمر ریدر در dispose لغو می‌شوند؛
- wordTick فقط صفحهٔ جاری را زیر RepaintBoundary بازمی‌سازد؛
- یک باگ تأخیری واقعی پیدا و رفع شد: اولین ضربهٔ کلمه در هر صفحه تا رسیدن پاسخ شبکه بی‌پاسخ بود (کامیت «a word tap always lands within a frame»).

### ۵-۲. پیشنهادهای ارتقا — عملکرد
1. **پیش‌بارگذاری همسایه‌ها با اولویت جهت سوایپ** (صفحات ±1,±2 در idle؛ اگر جهت آخرین سوایپ رو به جلو است، +2 زودتر از -2 گرم شود) — پیچش سرد را تقریباً حذف می‌کند.
2. **کش LRU تصویر leaf صفحه‌گردان** با سقف حافظه (مثلاً ۳ برگه) — الان snapshot تک‌برگه است؛ در پیمایش سریع چند برگه پشت هم، capture ممکن است از مسیر بحرانی گذر کند.
3. **کش دیسک فونت به‌صورت یکجا**: بارگذاری ۴۸ فونت در start اول به‌صورت batch (الان per-family است).

### ۵-۳. پیشنهادهای ارتقا — امکانات

### ۵-۴. پیشنهادهای ارتقا — دیزاین و ظاهر
